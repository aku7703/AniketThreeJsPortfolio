Lesson 2 / 14

DP vocabulary, then Fibonacci

A subproblem is a smaller instance whose answer helps solve the original. A state is the information that uniquely describes one subproblem. A recurrence is a rule for its answer using smaller states. A base case is a state solved directly.

Overlapping subproblems recur in different branches. Memoization stores answers during recursion (top-down). Tabulation fills a table in dependency order (bottom-up). Optimal substructure means an optimal solution can be assembled from optimal solutions to the relevant smaller states.

Fibonacci counts a sequence: define F(0)=0 and F(1)=1, then each next value is the sum of the previous two. The tree for F(5) repeats F(3), F(2), and smaller calls. DP solves each distinct state once.

F(n)=F(n−1)+F(n−2)(n≥2)F(n)=F(n-1)+F(n-2)\quad(n\ge2)F(n)=F(n−1)+F(n−2)(n≥2)

With constant-time arithmetic, both memoization and tabulation take Θ(n) time. Memoization uses Θ(n) table and stack space; keeping only the previous two values uses Θ(1) auxiliary space.

What makes memoized Fibonacci fast?

The states are the same. Repeated non-base computations become lookups. Recursion still exists.

Lesson 3 / 14

Design a DP before writing loops

An optimal value is the best score or minimum cost. A solution witness is the actual chosen coins, items or characters. Traceback follows choices through a completed table to recover that witness.

The six-line answer scaffold

1. State: exactly what does each entry mean?
2. Base cases: empty input, zero capacity, impossible states.
3. Recurrence: enumerate the last choice or last event.
4. Order: compute dependencies first.
5. Correctness: every optimum is represented; each candidate is feasible.
6. Cost + reconstruction: states × work/state; recover choices.

A state must contain every restriction that changes future choices. For unlimited coins, the remaining amount is enough. For items that can be used once, the set of items still available matters, so include a prefix index.

Why is “take the best smaller answer” not a proof?

Specify which smaller state, why it remains feasible, and why every optimal solution belongs to one of your cases. Then show the algorithm evaluates those cases only after their dependencies are correct.

Can remaining capacity alone describe 0/1 knapsack?

The same capacity with different available items can have different optimal values.

Lesson 4 / 14

Coin change: minimize the last coin

A denomination is an allowed coin value. Coins are positive integers and each denomination is available without limit. The target is a nonnegative integer amount V. Let C(a) be the fewest coins making exactly amount a; ∞ marks impossible amounts. There are k denominations.

C(0)=0,C(a)=min⁡d≤a{1+C(a−d)}(a>0)C(0)=0,\qquad C(a)=\min_{d\le a}\{1+C(a-d)\}\quad(a>0)C(0)=0,C(a)=d≤amin​{1+C(a−d)}(a>0)

An empty minimum is ∞. With coins {1,3,4}, amount 6, choosing 4 first leads to 4+1+1, but 3+3 uses only two coins. DP compares all possible final coins. For C(6), candidates are 1+C(5)=3, 1+C(3)=2 and 1+C(2)=3.

C[0] = 0
for a = 1 .. V inclusive:
    C[a] = infinity
    for d in denominations:
        if d <= a:
            C[a] = min(C[a], 1 + C[a-d])
return C[V]

Fill increasing amounts because a−d is smaller. Time Θ(kV) for the shown loops, auxiliary space Θ(V).

What changes if coin 1 disappears and coins are {3,4}?

The states for amounts 1,2,5 become impossible. Keep ∞, not 0, so an unreachable prefix cannot create a fake solution. Amount 6 is still 3+3.

Lesson 5 / 14

Recover coins and memoize safely

A parent choice records which final coin attained the minimum at each reachable amount. Store a denomination d whenever it improves C(a); ties may choose either optimum.

if 1 + C[a-d] < C[a]:
    C[a] = 1 + C[a-d]
    choice[a] = d

if C[V] == infinity: return impossible
coins = []; a = V
while a > 0:
    d = choice[a]
    append d to coins
    a = a - d
return coins

At target 6 with {1,3,4}, follow 6 → 3 → 0, emitting 3 and 3. Every step decreases the amount by a positive coin. Target 0 returns an empty list. Reconstruction takes O(number of coins), at most O(V) when denominations are positive integers.

Write a top-down version before opening
memo[0] = 0
function solve(a):
    if a < 0: return infinity
    if a in memo: return memo[a]
    best = infinity
    for d in denominations:
        best = min(best, 1 + solve(a-d))
    memo[a] = best
    return best

Cache impossible results too. Test membership rather than truthiness: 0 is a valid stored answer. Positive coins ensure termination. At most V+1 nonnegative states are cached, each considers k coins; O(kV) time, O(V) table plus O(V) recursion depth.

What must happen before traceback starts?

An impossible target has no valid parent chain. Return impossible instead of reading an unset choice.

Lesson 6 / 14

0/1 knapsack: which items remain?

Item i has positive integer weight wᵢ and nonnegative value vᵢ. The capacity W is the maximum total weight. 0/1 means each item is taken at most once. Let K(i,c) be the maximum value using only the first i items with total weight at most c.

K(0,c)=K(i,0)=0K(0,c)=K(i,0)=0K(0,c)=K(i,0)=0
K(i,c)={K(i−1,c)wi>cmax⁡{K(i−1,c),vi+K(i−1,c−wi)}wi≤cK(i,c)=\begin{cases}K(i-1,c)&w_i>c\\\max\{K(i-1,c),v_i+K(i-1,c-w_i)\}&w_i\le c\end{cases}K(i,c)={K(i−1,c)max{K(i−1,c),vi​+K(i−1,c−wi​)}​wi​>cwi​≤c​

Both choices move to row i−1. Taking item i adds its value and removes its weight and its availability. In the official example, pairs are (weight,value): (2,3),(3,4),(4,5),(5,6), with W=5. At K(2,5), skip gives 3; take gives 4+K(1,2)=7.

initialize row 0 and column 0 to 0
for i = 1 .. n inclusive:
    for c = 1 .. W inclusive:
        K[i,c] = K[i-1,c]
        if weights[i] <= c:
            K[i,c] = max(K[i,c], values[i]+K[i-1,c-weights[i]])
return K[n,W]

Time Θ(nW), auxiliary table space Θ(nW). Items are 1-indexed in this pseudocode.

Lesson 7 / 14

Knapsack traceback and the reuse trap

Start at (n,W). Compare the current entry to the one directly above it. Equality means you may skip the current item while preserving an optimum. Otherwise it must be taken; decrease capacity by its weight. Decrease i in both cases.

chosen = []; i = n; c = W
while i > 0:
    if K[i,c] == K[i-1,c]:
        i = i - 1
    else:
        append i to chosen
        c = c - weights[i]
        i = i - 1
return chosen

Official example: (4,5) → (3,5) → (2,5), skip items 4 and 3; take item 2 to (1,2); take item 1 to (0,0). The witness has weight 5 and value 7. A tie can represent multiple optimal witnesses; skipping on ties returns one of them.

One array changes the loop direction

For value only, store one capacity array. Iterate c downward for each item so dp[c−wᵢ] still belongs to the previous row. Upward iteration can use the same item again. With one item (2,3), W=4, upward updates incorrectly return 6; the 0/1 answer is 3.

for each item (w,v):
    for c = W down to w inclusive:
        dp[c] = max(dp[c], v + dp[c-w])

This uses O(W) value space, but loses the full table used by the simple traceback above.

Why does the take branch use i−1?

Once item i is chosen it is no longer available; row i−1 limits future choices to earlier items.

Lesson 8 / 14

LCS: preserve order, allow gaps

A subsequence keeps relative order but may skip characters. A substring must be contiguous. A prefix is the initial part of a string. Let X have length m and Y length n. L(i,j) is the length of a longest common subsequence of the first i characters of X and first j of Y. Characters below are 1-indexed.

L(0,j)=L(i,0)=0L(0,j)=L(i,0)=0L(0,j)=L(i,0)=0
L(i,j)={1+L(i−1,j−1)X[i]=Y[j]max⁡{L(i−1,j),L(i,j−1)}X[i]≠Y[j]L(i,j)=\begin{cases}1+L(i-1,j-1)&X[i]=Y[j]\\\max\{L(i-1,j),L(i,j-1)\}&X[i]\ne Y[j]\end{cases}L(i,j)={1+L(i−1,j−1)max{L(i−1,j),L(i,j−1)}​X[i]=Y[j]X[i]=Y[j]​

Match: extend an optimum for both shorter prefixes. Mismatch: at least one final character must be left out. Read top, left and diagonal cells only after they are filled. Row-major order works.

Official example AGGCT / AGCATA has LCS AGCT of length 4. The gap is allowed. Time Θ(mn), table space Θ(mn).

Why not return 0 at a mismatch?

That would erase subsequences already found and resembles a different contiguous-string problem. For LCS, preserve the better of the two ways of skipping a final character.

Lesson 9 / 14

LCS traceback: read the route backwards

Begin at (m,n). Equal characters contribute one output character and a diagonal move. On a mismatch, follow a neighbor whose value equals the current optimum. Either neighbor is valid on ties. Stop when either prefix is empty. Reverse the collected characters because traceback visits them from the end.

out = []; i = m; j = n
while i > 0 and j > 0:
    if X[i] == Y[j]:
        append X[i] to out
        i = i - 1; j = j - 1
    else if L[i-1,j] >= L[i,j-1]:
        i = i - 1
    else:
        j = j - 1
return reverse(out)

Small example ABC / AC: match C at (3,2), skip B, match A at (1,1). Collected C,A reverses to AC. Traceback takes O(m+n), with O(L(m,n)) output space, in addition to the table.

X=AB and Y=BA: how many optimal LCS witnesses?

The optimal length is 1. Both A and B preserve order in both strings; AB does not. A traceback tie need not be an error.

What changes if the problem asks only for the length?

You can keep two rows, or an appropriately managed single row, using O(min(m,n)) working space. Recovering characters with the simple method above still needs the full table.

Lesson 10 / 14

Edit distance: account for each operation

Unit-cost edit distance is the fewest insertions, deletions or substitutions converting A into B; each costs 1. A matching character costs 0. Let D(i,j) be the distance from A’s first i characters to B’s first j characters.

May not be on this quiz; study it after the other three.

D(0,j)=j,D(i,0)=iD(0,j)=j,\quad D(i,0)=iD(0,j)=j,D(i,0)=i
D(i,j)={D(i−1,j−1)A[i]=B[j]1+min⁡{D(i,j−1),D(i−1,j),D(i−1,j−1)}A[i]≠B[j]D(i,j)=\begin{cases}D(i-1,j-1)&A[i]=B[j]\\1+\min\{D(i,j-1),D(i-1,j),D(i-1,j-1)\}&A[i]\ne B[j]\end{cases}D(i,j)={D(i−1,j−1)1+min{D(i,j−1),D(i−1,j),D(i−1,j−1)}​A[i]=B[j]A[i]=B[j]​

Left = insert B[j]; above = delete A[i]; diagonal = substitute. For an empty target, delete i characters; for an empty source, insert j characters. Fill rows left to right, from top to bottom.

kitten → sitting: name the three edits

kitten → sitten (substitute k→s); sitten → sittin (substitute e→i); sittin → sitting (insert g). Distance 3. (The notes’ prose calls the second edit an insertion; it is a substitution.)

i = m; j = n; reverseEdits = []
while i > 0 or j > 0:
    if i > 0 and j > 0 and A[i] == B[j]:
        i--; j--
    else if i > 0 and j > 0 and D[i,j] == 1+D[i-1,j-1]:
        record substitution; i--; j--
    else if i > 0 and D[i,j] == 1+D[i-1,j]:
        record deletion; i--
    else:
        record insertion; j--
reverse the recorded alignment operations

Run forward through the recovered alignment to apply edits; raw positions shift after an insertion/deletion. Time Θ(mn), table space Θ(mn), traceback O(m+n).

Lesson 11 / 14

Prove it, then count the work

An induction hypothesis assumes earlier states have correct values. A loop invariant states what remains true before each iteration. A dependency order makes the two fit together.

Coin-change proof in two directions

Take any optimum making a>0 and remove its final coin d. Its remaining coins make a−d. Replacing that remainder by a smaller optimal remainder cannot hurt, so the recurrence considers a solution at least as good as the optimum. Conversely, every finite candidate appends a real coin to a feasible smaller solution, so it is feasible and cannot beat the true optimum. Thus the minimum equals the optimum. Amount 0 and impossible amounts are handled explicitly.

Turn recurrence correctness into algorithm correctness

Before filling C(a), every C(0)…C(a−1) is correct. Initialization: C(0)=0. Maintenance: positive d means every C(a−d) used is already correct, and the recurrence above gives C(a). Termination: after filling V, return C(V).

Count states × transitions per state

Coin:     (V+1) states × k choices       → Θ(kV) time, Θ(V) space
Knapsack: (n+1)(W+1) states × O(1) work  → Θ(nW) time, Θ(nW) space
LCS/edit: (m+1)(n+1) states × O(1) work  → Θ(mn) time, Θ(mn) space

State dimension alone does not give runtime: coin change has one dimension but k work per amount.

What changes if a coin denomination is zero?

Then a−d need not be smaller, so recursive evaluation may fail to terminate and the dependency proof breaks. Require strictly positive denominations.

Lesson 12 / 14

Recognize a familiar DP in a new story

A reduction translates a new problem into an already understood one while preserving feasible solutions and their values.

A string needs insertions to become a palindrome. Model it.

Let P(i,j) be the fewest insertions making the interval s[i…j] a palindrome. P=0 when i≥j. Equal ends: P(i+1,j−1). Unequal ends: 1+min(P(i+1,j),P(i,j−1)). Fill by increasing interval length. O(n²) time/space. For abc, two insertions suffice (abcba). Equivalently the answer is n−LCS(s,reverse(s)).

Fewest squares summing to N?

Coin change with denominations 1²,2²,…,⌊√N⌋² and unlimited copies. S(0)=0; S(a)=1+min S(a−q²) over q²≤a. O(N√N) time and O(N) space. For 12, 4+4+4 uses 3 terms; two squares cannot sum to 12.

Choose one-time assignments to earn at least P points in minimum hours.

Let H(i,p) be minimum hours using the first i assignments to earn at least p more points. H(i,0)=0; H(0,p>0)=∞. With item i earning rᵢ points in hᵢ hours: min(H(i−1,p), hᵢ+H(i−1,max(0,p−rᵢ))). Fill increasing i and p=0…P. O(nP) time and space; trace whether you took each assignment. For (points,hours)=(3,2),(4,5),(2,1), P=5, choose the first and third for 3 hours.

Reconcile two ordered transaction records with missing or changed entries.

Use edit distance on sequences of transactions. Deleting an unmatched personal entry, inserting a missing bank entry, or substituting a changed amount costs one discrepancy. Equal transactions cost zero. The same prefix states and boundary cases apply. For [10,20] and [10,25,30], substitute 20→25 and insert 30, for 2 discrepancies.

Give realistic coin-change and knapsack models.

Coin change: minimum reusable packet sizes to supply an exact resource requirement. Knapsack: choose at most one of each proposed project to maximize value under a time budget. State the integer units, reuse rule and objective; changing these can change the algorithm.

Lesson 13 / 14

Fresh questions: what changes and why?

Change one condition, predict the effect, and explain the dependency that caused it. Use the scratchpad or your own saved notes before revealing.

Find the bug before seeing the repair

Coin DP sets C[a]=0 for every a. What fails?

Unreachable positive amounts look free. Initialize C[0]=0 and every other amount to ∞; a solution is feasible only when its predecessor is finite.

LCS mismatch adds one to the diagonal. What fails?

A mismatch cannot contribute a common character. Choose max(top,left). For A/B the incorrect rule returns 1; the correct length is 0.

Knapsack take branch reads K(i,c−wᵢ). What fails?

It allows item i again. For a single (2,3) item and capacity 4, this can return 6. Using row i−1 correctly gives 3.

Edit-distance traceback stops when either index reaches 0. What fails?

Unmatched characters in the other prefix still require insertions or deletions. Continue while i>0 OR j>0. Example empty string → ABC needs three insertions.
